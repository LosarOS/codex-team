# Проверка настольной версии

Автоматические проверки находятся в `tests/test_desktop.py`. Они используют временный каталог приложения, локальные сокеты и тестовые объекты сервера/окна. Реальный Codex и модельные вызовы в них не запускаются.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Первый запуск | Настройки, журналы и рабочее состояние создаются в каталоге приложения внутри `%LOCALAPPDATA%`; установочные ресурсы не изменяются. |
| Повторный запуск | Изменённые пользователем инструкции и настройки сохраняются. |
| Установочные ресурсы | Пути работают как из исходников, так и из собранного приложения; текущий каталог не определяет расположение ресурсов. |
| Занятый порт | Приложение выбирает доступный loopback-порт или возвращает понятную ошибку; чужой процесс не останавливается. |
| Нет авторизации ChatGPT | Окно запускается и показывает состояние входа; обходной API backend не включается. |
| Сервер не готов | После ограниченного ожидания запуск завершается с диагностикой и освобождает ресурсы. |
| Ошибка сервера | Ошибка сообщается вызывающему коду; окно не показывает неработающий интерфейс как готовый. |
| Второй экземпляр | Общая блокировка предотвращает двух писателей; первый экземпляр остаётся работоспособным. |
| Обычное закрытие | Сервер завершается, сокет и блокировка освобождаются. |
| Закрытие во время задачи | Текущий исполнитель прерывается; частичные изменения и состояние задачи сохраняются. |
| Журналы | Записи сохраняются в каталоге приложения, без токенов, паролей и API-ключей. |

Перед выпуском дополнительно проверить собранный Windows `.exe` в чистом профиле: запуск двойным щелчком, отсутствие лишнего терминального окна, появление отдельного окна приложения, повторный запуск после закрытия, запуск из каталога с кириллицей и пробелами. Проверить отсутствие записи в каталог установки, сохранение настроек после перезапуска и сообщение о недостающем системном компоненте, если такой компонент требуется сборке.

Проверку входа через официальный Codex и полноценную задачу выполнять отдельно, только по явному разрешению пользователя. Наличие отдельного окна само по себе не подтверждает работу WebView2, входа, установленного Codex или модельных вызовов в чистой Windows-среде.
