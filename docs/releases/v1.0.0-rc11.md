# Codex Team 1.0.0-rc11 — диагностика проектов и управляемая очередь

Предварительная версия для Windows 10/11 x64. **Неподписанные бинарники:** возможны предупреждения SmartScreen. Stable 1.0.0 пока не объявляется.

- **Project Doctor — Windows/.NET:** действие на карточке проекта читает Git-исходники, решения, .csproj, global.json, lock-файлы, build scripts и workflows. Показывает локальную среду, рекомендации и происхождение данных. Ничего не устанавливает и не выполняет.
- **Проверка пакета:** локальная предварительная проверка очереди без вызова модели. Проекты, чистота Git, изоляция, доступ и порядок проверяются перед подтверждением. Изменившийся пакет нужно проверить заново.
- **Причины блокировки:** вход, лимит, решение пользователя, ошибка, прерывание, права и неизвестный результат различаются; видны состояние связанного запуска и оставшиеся задания.
- **Надёжность:** изменение порядка теперь сохраняется одной SQLite-транзакцией. Ошибка записи не оставляет половину обмена.
- **Русский / English**, существующие темы, включая Obsidian Violet, Neon Blue, Emerald Tech и Crimson Night, сохранены. Изменения независимых worktrees по-прежнему не объединяются автоматически.

## Установка и portable

Скачайте `CodexTeam-Setup-x64.exe`, установите для текущего пользователя и запустите через ярлык. Нужен Microsoft Edge WebView2 Runtime. Альтернатива — распаковать `CodexTeam-Portable-x64.zip` полностью в доступный для записи каталог и открыть `CodexTeam.exe`. `CodexTeam-Setup-x64.zip` содержит установщик. Контрольные суммы публикуются в `SHA256SUMS.txt` только вместе с реально собранными файлами.

Существующие настройки, проекты, история, очередь и независимые worktrees сохраняются; миграция формата пользовательских данных не требуется. После перезапуска очередь ждёт явного запуска.

## Ограничения и доказательства

Project Doctor выполняет статический анализ отслеживаемых Git-файлов. Условия MSBuild и импортированные свойства не вычисляются. Найденный SDK не доказывает успешную сборку. Компиляция, Windows publish, installer smoke и интерактивная GUI-приёмка показаны раздельно. Предварительная проверка очереди не гарантирует доступность AI-провайдера.

Проверки этой сессии и оставшиеся gates: [engineering report](https://github.com/LosarOS/codex-team/blob/v1.0.0-rc11/reports/engineering-session-2026-10-23.md). Native build/installed backend evidence поставляется в `build-verification.json`, `installed-smoke.json`, `portable-smoke.json`, `source-test-results.json` и `BUILD-NOTES.txt` при успешной сборке. Portable smoke запускает извлечённый frozen backend с изолированной папкой данных; выбор папки через GUI и интерактивная WebView2/DPI-приёмка на физическом Windows ПК остаётся отдельным этапом; браузерные fixture-снимки её не заменяют.
