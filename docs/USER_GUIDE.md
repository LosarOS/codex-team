# Руководство пользователя Codex Team

Это руководство описывает версию **1.0.0-rc1**: подготовку проекта, запуск команды, управление задачей и просмотр результата.

> Приёмка RC ещё не завершена. В финальной установленной сборке обнаружена проблема выбора профиля данных: прежний тестовый запуск отсутствовал в текущей истории. Если история выглядит пустой после смены сборки, сохраните прежнюю и текущую папки данных и проверьте используемый путь. [Статус проверок](../reports/final-release-validation.md).

## 1. Установите и откройте приложение

На GitHub пока опубликованы исходники без готовых файлов релиза. Для самостоятельной сборки следуйте [README](../README.md#установка-и-сборка) и [инструкции установки](../INSTALL_WINDOWS.md).

Если у вас уже есть собранный установщик, запустите `CodexTeam-Setup-x64.exe`, затем откройте **Codex Team** через ярлык. Установка выполняется для текущего пользователя. Для переносной версии распакуйте весь архив и запустите `CodexTeam/CodexTeam.exe`. Сохраните рядом папку `_internal` и другие файлы комплекта.

Для повседневной работы терминал не требуется. Инструменты сборки и тестирования самого проекта должны быть установлены отдельно.

## 2. Подключите аккаунт

Проверьте состояние подключения в приложении. По умолчанию используется **Codex / ChatGPT**. Если вход необходим, выполните официальный вход через браузер или код устройства и вернитесь в приложение.

Ключ API для этого способа не нужен. Использование зависит от доступных возможностей и лимитов аккаунта. Если вы специально выбираете **OpenAI API**, потребуется собственный ключ и подтверждение отдельной оплаты; ключ сохраняется в Windows Credential Manager. Приложение не включает платный API автоматически. [Подробности подключения](PROVIDERS.md).

## 3. Подготовьте проект

Откройте **«Проекты»** и выберите корень нужного Git-репозитория. Для изолированного запуска репозиторий должен содержать хотя бы один коммит, а рабочее дерево должно быть чистым. Сохраните текущие изменения коммитом или иным подходящим для вашего проекта способом.

Codex Team создаёт отдельную рабочую копию Git (`worktree`) для задачи. Убедитесь, что доступны инструменты проекта и известна команда проверки: например, тесты, сборка или проверка типов.

## 4. Сформулируйте задачу

Укажите желаемый результат, область изменений, ограничения и признаки успешного завершения. Чем конкретнее эти сведения, тем проще проверить работу команды.

Пример:

> Исправь округление итоговой цены в корзине. Добавь тесты для дробной цены и скидки 100%. Сохрани текущий интерфейс и формат ответа сервера. Запусти тесты проекта. В итоговом отчёте перечисли изменения, выполненные проверки и оставшиеся ограничения.

Для реализации готового плана приложите сам план и критерии приёмки. Для аудита укажите, какие свойства нужно проверить и какой отчёт вы ожидаете.

## 5. Выберите режим и набор агентов

| Режим | Ожидаемый результат |
| --- | --- |
| Quick | Небольшое изменение с проверкой тестировщиком |
| Standard | Реализация с анализом, тестированием и ревью |
| Deep | Реализация с дополнительными специалистами и финальным аудитом |
| Audit | Отчёт о состоянии проекта без реализации исправлений |
| Plan | Анализ и план решения без реализации |
| Implement | Реализация уже сформулированного решения с тестами и ревью |

Для первой обычной задачи выберите **Standard** и подходящий набор агентов. При необходимости состав настраивается в разделе **«Наборы»**. Дополнительные специалисты работают последовательно и только для чтения; код меняет разработчик. [Настройка агентов и наборов](AGENT_PACKS.md).

Нажмите **«Запустить команду»**. Откройте **«Запуски»**, чтобы наблюдать за текущим этапом, сообщениями агентов и результатами команд.

## 6. Управляйте работой и отвечайте на запросы

| Кнопка | Как использовать |
| --- | --- |
| «Пауза» | Дождаться завершения текущего этапа и приостановить дальнейшую работу |
| «Стоп» | Отменить текущую работу |
| «Направить» | Передать уточнение текущему агенту, когда это поддерживается, и сохранить его для дальнейших этапов |
| «В очередь» | Передать уточнение следующему этапу |
| «Продолжить» | Возобновить задачу из сохранённой контрольной точки |

В подробностях запуска **Agent Mission Control** показывает последовательность этапов и отдельные попытки при повторной работе агента. Нажмите этап, чтобы открыть инспектор: результат, проверки, фактическое время начала/завершения, последние события и токены роли за весь запуск. Если сведений нет, интерфейс сообщает об этом; проценты готовности не вычисляются.

Под этапами видны текущий или последний агент и последнее полученное событие. «Направить» переводит к полю указания, «Логи» открывает ленту событий. В ленте доступны фильтры агентов, команд, ошибок и решений пользователя. Старые раскрытые записи сохраняются при поступлении новых; кнопка загрузки позволяет повторить запрос после ошибки. При большой истории события подгружаются страницами, в видимой ленте остаются последние 600 загруженных записей. Времена попыток сохраняются из событий; время работы запуска — последнее сохранённое backend значение, а не непрерывный секундомер.

Например, если вы забыли ограничение по интерфейсу, передайте: «Сохрани существующие названия полей ответа сервера». Для пожелания к следующему этапу используйте очередь.

Если задача ожидает решения, откройте **«Центр действий»**. Прочитайте причину запроса, команду или операцию и область доступа. Разрешите или отклоните действие через доступные варианты. Разрешения на одну операцию или сеанс доступны там, где их поддерживает официальный SDK. Если механизм недоступен, приложение показывает ограничение. Решение о продолжении задачи само по себе не выдаёт разрешение на выполнение команды. [Подробнее](PERMISSIONS.md).

## 7. Проверьте результат

После завершения откройте карточку запуска и просмотрите:

- Итоговый отчёт и замечания ревьюера.
- Выполненные команды, результаты тестов и коды завершения.
- Изменения Git по файлам.
- Созданные артефакты и сведения об использовании.

Статус `DONE` относится к выбранному режиму. Для Plan он означает готовый план, для Audit — завершённую проверку. Убедитесь, что фактический результат соответствует вашей задаче и что нужные проверки действительно выполнены.

Изменения остаются в рабочей копии задачи. Приложение не выполняет автоматическое объединение веток и отправку в GitHub. После проверки перенесите или объедините изменения привычными инструментами Git и отправьте их самостоятельно.

## 8. Продолжите прерванную задачу

В **«Истории»** найдите запуск, откройте его и используйте **«Продолжить»**, если продолжение доступно. Завершённые этапы сохраняются; прерванный этап может выполняться повторно.

Не изменяйте рабочую копию вручную перед продолжением. Если состояние файлов или контрольная точка расходятся с сохранёнными данными, приложение потребует отдельного решения. При аварийном завершении сообщение о восстановлении помогает обнаружить прерванный запуск.

История привязана к папке данных. У установленной версии это обычно `%LOCALAPPDATA%\CodexTeam`, у переносной — `data/` рядом с программой. Переменная `CODEX_TEAM_DATA_ROOT` может задавать другой путь. В текущем RC выбор профиля требует дополнительной проверки: пустая история после смены сборки не доказывает удаление старых данных.

## 9. Настройте приложение под себя

В **«Агентах»** можно менять инструкции, дублировать и отключать профили, импортировать и экспортировать конфигурации. Встроенные профили защищены от удаления. Настройки модели и глубины рассуждения наследуются независимо: агент → роль → общие настройки → Codex. Оставьте поле пустым для наследования.

В **«Настройках»** выберите тему, цвет акцента, уведомления и сворачивание в область уведомлений. Доступны системная, светлая, тёмная, фиолетовая неоновая и тема тёмного фэнтези.

При закрытии окна с активной задачей выберите: оставить работу в области уведомлений, остановить задачу и выйти или отменить закрытие. Через значок в области уведомлений можно открыть окно и текущий запуск, поставить работу на паузу, открыть журналы или выйти.

## 10. Обновление и решение проблем

Автоматического обновления пока нет. Полностью закройте приложение, сделайте резервную копию используемых папок данных и установите новую сборку. Удаление приложения сохраняет данные, проекты и официальный вход.

| Ситуация | Что проверить |
| --- | --- |
| Приложение не запускается | Поддерживаемую Windows x64, WebView2 и целостность комплекта; у переносной версии — наличие `_internal` |
| Проект не принимается | Выбран ли корень Git, есть ли коммит, чистое ли рабочее дерево |
| Команда сборки или тестов не найдена | Установлены ли инструменты проекта и доступны ли они приложению |
| Задача ожидает решения | Запросы в «Центре действий», подключение и доступные лимиты |
| Продолжение недоступно | Сохранённую контрольную точку и состояние рабочей копии |
| История пуста после обновления | Папку данных установленной/переносной версии и `CODEX_TEAM_DATA_ROOT`; сохраните оба профиля |

Для обращения об ошибке экспортируйте диагностику через диалог сохранения, просмотрите архив и приложите подходящие сведения к [GitHub Issues](https://github.com/LosarOS/codex-team/issues). Укажите версию приложения, Windows, способ запуска и шаги воспроизведения. Не передавайте ключи и другие секреты.

Дополнительные сведения: [решение проблем](../TROUBLESHOOTING.md), [безопасность](../SECURITY.md), [ограничения](../LIMITATIONS.md), [обзор проекта](../README.md).


## 11. Рабочие инструменты V2.1

Навигация объединяет рабочие страницы, подготовку задач, качество и управление. Mission Control остаётся подробным просмотром запуска: pipeline, журнал, diff, проверки и команды управления доступны в одном разделе «Запуски».

В **AI Task Architect** сначала сохраните черновик. AI-подготовка запускается только после отдельного подтверждения. Кнопка отмены сохраняет исходный черновик. Если provider завершает операцию медленно, новая подготовка будет временно заблокирована до безопасной очистки; поздний результат отменённого вызова не заменяет ТЗ. Редактирование во время подготовки защищено проверкой версии.

В **Git Time Machine → Хранение контрольных точек** очистка по умолчанию выключена. Настройте число/возраст, откройте предпросмотр и отдельно подтвердите удаление ссылок. Точки запусков, истории, восстановленных копий и необходимые Git-ссылки защищены. Указанный логический размер не равен освобождаемому месту; приложение не выполняет принудительный Git GC и не изменяет исходное рабочее дерево.

В **QA Arena → Настройка среды** проверьте Docker с локальным Linux daemon, выберите уже существующий доверенный образ и подтвердите проверку его immutable ID/digest. Затем просмотрите обнаруженные команды, сохраните конфигурацию и подтвердите конкретный снимок для пробного запуска. Проверка образа выполняет только чтение метаданных. Образы и зависимости автоматически не скачиваются. Если Docker или инструменты недоступны, интерфейс показывает причину и необходимые действия.

Quality Gate сохраняет FAIL при провале проверки, даже если остальной набор прерван. Отмена/недоступная среда означают BLOCKED, а неполный успешный набор — PARTIAL; отсутствие выполненных проверок не даёт PASS.

**Project Intelligence** повторно использует локальный анализ, проверяя HEAD, index и состояние файлов. Кнопка принудительного обновления перечитывает разрешённый контекст. **Budget Guardian** показывает пользовательский бюджет и наблюдаемое использование, а не официальный остаток квоты аккаунта.

Windows-приёмка новой версии описана в [release candidate report](../reports/v21-release-candidate.md). До её фактического выполнения статус Windows Desktop — NOT VERIFIED.
## Создание проекта и страницы инструментов

В разделе «Проекты» можно создать проект с нуля: укажите название и путь **новой** папки внутри существующего каталога. Приложение создаст локальный Git-репозиторий, README и первый коммит, затем выберет проект для новой задачи. GitHub-аккаунт не нужен; публикация на GitHub автоматически не выполняется. Существующие папки не перезаписываются — для них используйте подключение репозитория.

«Архитектор задач», «Знания проекта», «Бюджет запусков», «Машина времени Git» и «Проверка качества» открываются отдельными страницами из бокового меню. Выбранный проект сохраняется при переходе между ними.

## Уровень доступа Codex

Перед запуском выберите «Только чтение», «Рабочая папка» или «Полный доступ». Полный доступ отдельно подтверждается: агент-разработчик получает доступ к файлам за пределами проекта, командам и сети без дополнительных разрешений. Другие роли, аудит и планирование сохраняют ограничения чтения. Никакие глобальные конфиги Codex не редактируются.

Если задача уже остановилась с ошибкой песочницы, откройте запуск, выберите уровень доступа, нажмите «Применить», затем «Продолжить». Результаты, контрольная точка, история и фактический расход сохраняются; незавершённый этап получает новый сеанс Codex. Лимиты запуска автоматически не увеличиваются.

## Язык и цветовое оформление

В разделе **«Настройки → Внешний вид»** выберите **Русский** или **English**. Язык сохраняется в локальных настройках приложения. Переключение перезагружает интерфейс; если в формах есть несохранённые изменения, приложение сначала предлагает подтвердить переход. Отмена сохраняет введённый текст. Содержимое заданий, агентных инструкций, исходного кода и журналов автоматически не переводится.

Для нового профиля используется **Obsidian Violet**. Доступны также **Neon Blue**, **Emerald Tech**, **Crimson Night**, светлая, системная и прежние тёмные темы. Выберите вариант, при необходимости настройте акцент и нажмите **«Сохранить оформление»**. Язык сохраняется отдельно от оформления. Старые сохранённые темы и пользовательские данные не сбрасываются.

Каждая тема использует общие цвета поверхностей, текста, фокуса и статусов. Цвет акцента не меняет смысл предупреждений и ошибок. Системная тема следует светлому/тёмному оформлению операционной системы.
