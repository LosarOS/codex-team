# Codex Team — итоговый отчёт

> Исторический отчёт от 10 октября 2026. Его результаты относятся к прежней сборке и аккаунту; актуальные проверки и ограничения RC11 находятся в [отчёте сессии 23 октября](../reports/engineering-session-2026-10-23.md).

Дата: 10 октября 2026, Windows x64. Реализован локальный рабочий MVP над официальным Codex. Продвинутые возможности, отсутствующие в этой версии, перечислены явно.

1. **Что реализовано.** Python backend, localhost UI, CLI, независимые роли, шесть режимов, editable prompts, пять packs и custom specialists. SQLite history/events/settings, project memory, checkpoints, bounded repair loops, Pause/Stop/Steer/Queue/Resume, worktrees, diff, usage, model list и ChatGPT connection status.

2. **Архитектура.** `server.py`/`cli.py` → `engine.py` → `provider.py` → официальный `openai-codex==0.162.1` и pinned CLI runtime 0.162.1. Каждый агент получает отдельный настоящий thread, developerInstructions, permission profile и structured output schema. Native Codex выполняет свою работу; приложение передаёт задачи/артефакты и проверяет результаты. `workspace.py` отвечает за Git/границы, `storage.py` за SQLite и редактирование секретов, `context.py` за targeted context, `registry.py` за роли/packs. Подробности: [ARCHITECTURE](../ARCHITECTURE.md).

3. **Запуск.** В PowerShell из корня: `./setup.ps1`, затем `./run.ps1`. На данном ПК `.venv` уже установлен. UI: http://127.0.0.1:8765. `./run.ps1 -NoBrowser` запускает только сервер. Python 3.11+ и Git обязательны. Node.js не нужен backend. Setup умеет использовать имеющийся bundled Python вместо сломанного WindowsApps alias. См. [INSTALL_WINDOWS](../INSTALL_WINDOWS.md).

4. **Login.** Проверяется официальный `account/read` и именно тип ChatGPT. Существующая авторизация Codex автоматически обнаружена и использована в реальных вызовах. CONNECT CHATGPT / Device Code Login используют `account/login/start`; вход завершает пользователь в официальном flow. CLI: `.\.venv\Scripts\ai-team.exe login [--device]`. Credentials остаются в штатном хранилище Codex; приложение не читает auth.json и не копирует токены. Новая интерактивная авторизация не потребовалась и не проверялась.

5. **API key.** Не требуется. Единственный активный backend — `codex_chatgpt`; принудительно выбраны официальный OpenAI provider и ChatGPT-only login. API credentials в дочернем runtime обнуляются. Отдельный API provider отсутствует, automatic billing fallback отсутствует. Это использует Codex usage текущего ChatGPT-плана, а не обещает неограниченные запросы.

6. **Официальные возможности.** SDK app-server client, account read/login, thread start/resume/fork, turn start/stream/steer/interrupt, structured output, developer instructions, native permission profiles, approval events, model list и account rate limits. Fork доступен в адаптере, candidate pipeline не построен. Реальные turn notifications содержат фактические команды, результаты и token usage.

7. **Ограниченные возможности.** Этапы выполняются последовательно; `max_parallel_agents` зарезервирован и не включает параллельную работу. Multi-solution отключён. Director — high-level task с автоматическим pipeline, без сложного DAG. Arbitrary per-agent tool/path ACL editor и grant-approval UI отсутствуют. Escalations отклоняются и требуют решения пользователя. QA/reviewer/specialists read-only. Optional API backend отсутствует. Полная таблица: [LIMITATIONS](LIMITATIONS.md).

8. **Первый проект.** Выберите чистый локальный Git root с первоначальным commit. При новом проекте создайте каталог, `git init`, добавьте исходные файлы и initial commit. В UI укажите этот root. Не выбирайте диск/home, подкаталог или каталог с несохранёнными изменениями. По умолчанию создаётся isolated worktree в `.ai-team/worktrees/run_ID` выбранного проекта; source checkout не получает автоматического переноса изменений.

9. **Custom agent.** Agents → Add Agent: lowercase identifier, инструкции, permission, optional model/effort. Для специалиста Deep/Audit выберите read-only и затем включите его в Specialists. Core QA/Reviewer нельзя превратить в writer. Built-in prompts: `agents/*.md`; packs: `packs/*.json`. Конфигурация run замораживается при создании, дальнейшее глобальное редактирование не меняет уже созданную задачу.

10. **Multi-agent task.** Задача + Git root + Standard → START. Pipeline: Coordinator → Analyst → Developer → QA → Reviewer. Quick опускает Analyst/Reviewer; Deep добавляет выбранных специалистов и Final Audit; Audit не редактирует код; Plan выдаёт анализ/архитектуру; Implement выполняет существующий план. QA/Reviewer FAIL возвращает работу Developer, затем повторяется validation tail. Обязательные роли/неразрешённые verdicts не позволяют выставить DONE. Calls, iterations и duration ограничены.

11. **Diff.** В UI вкладка Diff; CLI `.\.venv\Scripts\ai-team.exe diff run_ID`. Реальный Git diff включает tracked и untracked changes без подмены индекса. Paths и sensitive names проверяются до экспорта содержимого. Изменения находятся в worktree; перенос в основной checkout пользователь выполняет после просмотра. Auto-commit opt-in и выключен по умолчанию; push отсутствует.

12. **Остановка.** Pause — после завершённого этапа; Stop — native turn interrupt. Сервер закрывается Ctrl+C, CLI Ctrl+C сохраняет частичные изменения. Escalation permissions не предоставляются автоматически. One active run/process lease не допускает конкурирующих orchestrator writers; CLI execution требует остановить UI server.

13. **Продолжение.** Resume в UI или `.\.venv\Scripts\ai-team.exe resume run_ID`. Завершённые этапы сохраняются; незавершённый этап повторяется через прежний native thread. Проверяются HEAD/diff/content hashes, включая binary changes. Внешние изменения paused workspace блокируют resume. После crash/Stop частичные изменения сохраняются; приложение не может отличить их от одновременных ручных правок, поэтому diff нужно осмотреть.

14. **История.** `.ai-team/team.sqlite3` в корне приложения; UI History. Atomic snapshots: `.ai-team/runs/run_ID/state.json`. Память выбранного проекта: `.ai-team/project.json`, summary/map/architecture/commands/decisions/known_issues и run/artifact файлы. SQLite WAL и ОС lease допускают восстановление после аварии.

15. **Logs.** Timeline и events в SQLite содержат native command/result events, публичные сообщения и control actions. Hidden reasoning/raw response items не сохраняются. Нормализованный native execution ledger сохраняется отдельно в run. Секретные ключи и распространённые assignment patterns редактируются. Native profiles запрещают credential filename globs; это ограниченная защита по именам, не универсальный secret detector.

16. **Automated tests — PASS.** Полный финальный прогон: **184 passed, 2 skipped**, 312.08s; `reports/test-results.txt`. Оба skipped требуют привилегированного Windows symlink; NTFS junction проверки прошли. Одна deprecation warning Starlette/httpx TestClient не является failure. Покрыты modes/stage transitions, repair/rechecks, bad results, budget/usage, resume, external edits, competing processes/crash release, HTTP origin/Host/JSON guards, secret redaction, junction escape, Git hooks/filters и native test evidence. Fake provider используется только в unit tests. UI проверен на fixture в desktop/390px и на реальном сервере в desktop/375px: история DONE, пять threads, Diff/Tests/Usage, отсутствие overflow/console errors, custom-agent editing и literal rendering malicious text. JS и все PowerShell entrypoints проходят syntax check. Независимый итоговый review: `reports/final-review.md`, оставшихся concrete Critical/High findings нет.

17. **Real Codex integration.** `reports/provider-spike.json` — real ChatGPT account, independent native thread и фактическое чтение marker через native command, external MCP disabled, usage получен от SDK. Early high-level spike: `reports/sdk-spike.json`; он использовал inherited MCP после sandbox denial, поэтому narrow production proof отделён. Final native profile повторно проверен реальным SDK после исправления формата вложенных TOML overrides. Обычный TOML parser не заменяет runtime integration check.

18. **Demo — DONE.** `reports/demo.json` и `reports/demo.diff`: отдельный Python Git fixture, задача `validate_email`, isolated worktree, сохранённая исходная `normalize_name`. Developer добавил функцию и 12 test methods; полный suite 13 tests. QA независимо выполнил 13 tests, 901 validator probes, 4 normalization checks и сверил SHA-256 изменённых файлов с реальным orchestrator snapshot. Reviewer дал APPROVED, независимо прошёл 13 tests, 860 validator probes и 4 normalization checks. Пять отдельных native thread IDs; run `run_dae2bbff57d9` завершён без errors. Дополнительный host unittest и проверка QA ledger финальным execution gate: `reports/demo-validation.json`, `reports/demo-independent-tests.txt`. Промежуточные USER_DECISION_REQUIRED остаются в истории, не переписываются как успех.

19. **Известные ограничения.** Native Windows read-only sandbox на этом пути может отказать Set-Location/git cwd metadata; используются абсолютные reads/tests и real Git artifacts от host. Full-access fallback отсутствует. QA execution heuristic требует current-turn positive test count, exit0, successful summary и отсутствие observed native failed suite; unsupported wrappers могут требовать review. Это corroboration, не доказательство релевантности тестов или защиты от намеренно поддельного runner stdout. Credential globs native Windows pre-expand до depth16; новые/deeper пути и произвольные имена секретов не гарантированы. Host Git hooks отключены, active filters запрещены; semantic safety каждого in-workspace изменения обеспечивается review, не категоризацией shell. См. [TROUBLESHOOTING](../TROUBLESHOOTING.md).

20. **Следующая версия.** Parallel read-only groups с durable join; multi-task Director DAG; candidate worktrees и reviewed merge; per-agent policy editor; supported approval UI; Windows/runtime matrix и runner-specific evidence adapters. Optional API provider — только отдельным явным opt-in к другому billing. [ROADMAP](../ROADMAP.md).
