# Codex Team — product strategy / 2026

Дата discovery: 2026-11-14. Исходный master: `0269b3db6b8d485b6880784f827c9719984aaabb`, опубликованная версия RC11. Это план и source review, не подтверждение выпуска RC12.

## Аудитория и проблема

Разработчику, использующему агентов, трудно удерживать контекст, видеть ограничения, расход и фактический результат, а также безопасно интегрировать изменения. Продукт должен помогать принимать решения, а не рисовать фиктивный прогресс.

Сильные стороны: локальная SQLite-история, отдельные Git worktrees, explicit start, frozen budgets, command/access profiles, Project Doctor, QA evidence и existing Task Architect/Memory. Главные ограничения: один writer, независимая последовательная очередь, отсутствие безопасного автоматического merge; физическая WebView2/DPI и успешная live SDK разработка не подтверждены.

## Сценарии

1. Новая задача: добавить проект → проверить окружение → подготовить ТЗ и критерии → выставить бюджет/permissions → явно запустить → проверить diff/test/review.
2. Большая задача: вручную отредактировать план → проверить зависимости и общие файлы → подготовить независимый root step в форму → отдельно подтвердить запуск. Зависимые работы не отправляются в независимую очередь автоматически.
3. Блокировка: открыть Mission Control → понять фактическое состояние и причину → использовать существующее разрешённое действие. После неопределённого исхода не повторять запуск автоматически.
4. Контекст: просмотреть источники знаний и свежесть → исключить устаревшее → увидеть ограниченный payload до вызова AI.
5. Бюджет: выбрать проект/UTC-дни/страницу → посмотреть фактически доступные данные → явно экспортировать снимок, не выдавая страницу за всю историю.

## Ориентиры качества

[VS Code agent sessions](https://code.visualstudio.com/docs/agents/run/agents-window) и [review agent edits](https://code.visualstudio.com/docs/agents/run/review-code-edits) — ориентиры для явного разделения задачи, сессии, изоляции и принятия результата. ## Согласованный ближайший scope

1. **Mission Control:** реальная хронология и read-only рекомендации при auth/limit/decision/pause/interruption/failure. Не менять модель выполнения или подменять существующие кнопки разрешений.
2. **Task Architect:** отдельные версионированные планы, критерии, относительные файлы, зависимости и циклы. Детерминированный порядок и общие файлы — подсказки, не доказательство независимости. Подготовка выбранного root step не даёт автоматического разрешения на запуск.
3. **Project Memory:** привязка к revision/source hashes, состояния current/stale/review_required/unknown, исключение устаревшего контекста и bounded explicit preview. Старые записи остаются редактируемыми; их неподтверждённая свежесть не скрывается.
4. **Budget Guardian:** фильтруемый current-page export фактических данных с различением null/zero/partial. Отсутствующая цена и квота остаются недоступными. Снимок preview совпадает со скачиваемым JSON.

Общий UX: RU/EN новых controls, сохранение тем, явные loading/error/empty states и keyboard navigation. GitHub: русский download-first README, полный English, реальные снимки с происхождением и честные release notes.

## Риски и границы

- Git HEAD недостаточен для freshness: незакоммиченные изменения, удаление, untracking/ignored источника также должны исключать устаревший факт.
- Репозиторий и внешние знания — недоверенные данные, не system instructions. Ограничивать размер и состав контекста; не включать секреты намеренно.
- План устаревает после версии ТЗ; stale plan не должен молча запускать иной текст или обходить frozen budget/access confirmation.
- Декларированные paths не доказывают отсутствие конфликтов. Зависимый граф исполнения и автоматический merge остаются вне scope.
- Экспорт бюджетов относится к выбранной странице, а не всем запускам; без task text, приватных путей, сырых provider payloads и ключей.
- При отсутствии живой авторизации SDK ограничиться компонентными тестами. Не использовать платный API как скрытый fallback.

## Acceptance / evidence

Core Python, Node contracts, реальные API/Git/SQLite tests, stale/CAS/invalid-path/cycle cases, event dedup/order/foreign-run guards, date/pagination/privacy/unknown usage, browser theme/RUEN matrix, Windows packaging/preservation и WebView2 download flow. Фактические количества и непроверенные пункты записываются отдельно; исторические RC11 цифры не считаются результатом RC12.

Final release и merge в защищённую основную ветку требуют отдельного подтверждения владельца. Лицензия не меняется; неподписанные бинарники и физическая Windows/WebView2 приёмка не скрываются.
