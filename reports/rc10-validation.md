## Функция

MissionQueue хранит задания и идемпотентные UUID в отдельной SQLite-таблице. При добавлении локально проверяются проект и роли, фиксируются эффективные лимиты проекта; обращения к SDK/модели нет. Явный start запускает единственный dispatcher, который под прежним engine.lock вызывает обычные Engine.create/launch. Обработка агентов, разрешений, QA, worktrees и бюджетов остаётся прежней. После DONE запускается следующее задание; все другие исходы требуют вмешательства. Максимум20 незавершённых заданий. История не удаляется, ответ ограничен100 завершёнными+20 активными записями. Индексы ограничивают обход; карточки читают состояние запуска без загрузки его diff/артефактов в Python.

Очередь не включается после restart. Pause означает завершить текущую без старта следующей; остановка самого запуска доступна существующими командами. Shutdown: queue.close → architect/QA.close → engine.close → Store.close. Закрытие Engine служит барьером для незавершённой локальной подготовки. Сам dispatcher не повторяет неопределённый запуск после сбоя, а блокирует запись для ручной проверки.

Задачи независимы и требуют isolated=true; автоматического merge/переноса результатов между worktrees нет. Это явно объяснено при подготовке и в руководстве. Выбранный в настройках исполнитель используется на момент dispatch; утверждённые per-task лимиты заморожены. Full-access проходит обычное отдельное подтверждение.

## Безопасность и ограничения

UI вставляет задачи через textContent; полный текст доступен локально, preview и диагностика редактируются существующим sanitizer. SQL использует параметры. Сохранение задач не означает разрешение на выполнение; требуется отдельный start. Повторный enqueue не дублирует задание, повторный start не создаёт второй dispatcher. История/файлы запуска не удаляются при skip. Платные inference-запросы для тестирования не выполнялись.

При аварии между созданием run и сохранением его ссылки может остаться незапущенная запись run; очередь блокирует неопределённое задание и не повторяет его автоматически. Проверьте историю перед пропуском/повторным созданием. Безопасность важнее скрытого автоматического восстановления.

## Windows checklist

1. Обновить всю сборку; проверить старые данные, темы и язык.
2. Добавить две небольшие независимые задачи с низкими лимитами. До start модели не запускаются; после отмены форма сохранена.
3. Проверить порядок, полный текст, full-access confirmation и отказ без изоляции.
4. Явно запустить очередь, проверить связанный Mission Control. При DONE начинается следующая; при AUTH/решении/ошибке — нет.
5. «После текущей задачи» оставляет текущий запуск, запрещает следующий. Проверить штатный pause/stop через страницу запуска.
6. Закрыть и открыть приложение: задания сохранены, авторестарта нет. Проверить прерванный запуск, ручное восстановление либо skip.
7. Проверить RU/EN, все темы, клавиатуру, WebView2, DPI100/125/150/175%, updater.
